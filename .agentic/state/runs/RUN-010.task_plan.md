# RUN-010 Task Plan — última milha aprendida (token head condicionada)

Contexto: 3 estratégias de decode falharam (0%) porque as distribuições
de código não concentram no token certo — e o LCM provou que a última
milha conceito→texto exige **capacidade generativa aprendida**. Solução:
classificador de token condicionado nas saídas das heads piramidais.
Ablação embutida responde a pergunta-chave: **os códigos RVQ carregam
sinal além do feat?** — variante `feat` vs variante `feat+codes`,
mesmos dados, mesma capacidade.

Design: alvo = token VERDADEIRO do stream (supervisão real); métricas =
top-1 vs truth E vs argmax AR do backbone. Variante feat+codes consome
os códigos PREVISTOS pelas heads (frozen, argmax por nível, greedy com
condicionamento sequencial) — casamento treino/inferência. Um forward
do backbone serve as duas variantes.

## Branch Strategy

- decision: `current_branch` (`main`).

## Phases

- Phase 1: T001 | Phase 2: T002 (treino bg) | Phase 3: T003 | Phase 4: T004

## Tasks

### T001 — `scripts/train_token_head.py`

**Intent**: trainer novo. `TokenHead(d_in=256, V)`: proj(feat)→SiLU→
Linear V (~39M). `TokenHeadCodes`: mesmo tronco + entrada extra com
concat dos vetores de código previstos (frozen `LevelHeads` → greedy
argmax por nível → cw[k][c]). Alvo: `row[-1]` do stream (mesma
amostragem/seed do trainer de heads). Eval periódico em batch held-out:
top-1 vs truth e vs argmax AR. Checkpoint + `--resume`.
**Domain**: ml | **Risk**: low | **Deps**: []
**Acceptance**: script treina as DUAS variantes no mesmo loop (um
forward backbone compartilhado); logs periódicos de loss+acc; resume
funcional.

### T002 — Treino (background, ~1-1,5h)

**Intent**: `--steps 1500` sobre qwen_stream, saída
`artifacts/token_head_qwen05/`. Registrar losses/accs finais por
variante.
**Domain**: ml | **Risk**: low | **Deps**: [T001]
**Acceptance**: `final.pt` com as duas variantes; acc held-out final
por variante registrado; baseline documentada (random=1/152k).

### T003 — Eval + spec-decode (`artifacts/token_head_eval.json`)

**Intent**: em ≥100 posições held-out: top-1 de cada variante vs truth
e vs argmax AR; comparar com baselines medidos (near=0%, path=0%,
codebook solo 32%). Depois `spec_pyramid.py --score tokhead`: draft =
argmax do TokenHeadCodes sobre (feat, códigos do offset-head); medir
acceptance por offset vs RUN-007/009 (ambos 0).
**Domain**: ml | **Risk**: low | **Deps**: [T001, T002]
**Acceptance**: JSON com acc por variante/métrica; acceptance
spec-decode por offset; comparação direta com os zeros anteriores.

### T004 — Report + veredito arquitetural

**Intent**: seção em `artifacts/report.md`: as DUAS perguntas
respondidas — (a) a última milha aprendida fecha o token? (b) códigos
RVQ acrescentam sinal mensurável sobre feat-only? Se feat+codes >
feat-only > 0: a pirâmide vale; se feat-only ≈ feat+codes: o feat já
contém tudo e a pirâmide é redundante para este fim.
**Domain**: docs | **Risk**: low | **Deps**: [T003]
