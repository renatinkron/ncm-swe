# RUN-014 Task Plan — NCM nativo escopo-fechado (TinyStories)

Contexto: spec `.agentic/research/ncm-closed-scope-training-plan.md`
(domínio TinyStories confirmado, vocab 8k). Pipeline nativo já
existe: CorpusBPE → VQ-VAE multi-level → LevelGenerator +
ARBaseline (scripts/train_generator.py --model ncm|ar).

## Branch Strategy

- decision: `current_branch` (`main`).

## Phases

- P1: T001 | P2: T002 | P3: T003 | P4: T004∥T005 (bg, dias) | P5: T006

## Tasks

### T001 — Download TinyStoriesV2 + BPE 8k

**Intent**: baixar `TinyStoriesV2-GPT4-train.txt` (~2,2GB) +
valid.txt para `data/tinystories/`; shard em arquivos; treinar
CorpusBPE vocab=8192 → `artifacts/bpe_ts.json`. Validar encode/
decode roundtrip.
**Domain**: data | **Risk**: low | **Deps**: []
**Acceptance**: bpe_ts.json salvo, vocab 8192, roundtrip correto
em amostras, meta.json com stats do corpus.

### T002 — VQ-VAE (tokenizer NCM) no corpus

**Intent**: `train_vqvae.py` com corpus TinyStories segmentado via
bpe_ts (in_vocab_size=8192, ctx 128) → `artifacts/tokenizer_ts.pt`.
Smoke primeiro; treino até convergir razoável (monitorar loss +
codebook usage por nível).
**Domain**: ml | **Risk**: med (bg horas) | **Deps**: [T001]
**Acceptance**: tokenizer_ts.pt; codebook levels vivos (sem
colapso); reconstrução de amostras documentada (qualidade).

### T003 — Encode corpus → codes

**Intent**: `encode_corpus.py --bpe bpe_ts --tokenizer
tokenizer_ts --out-dir artifacts/codes_ts` → train.npy + held.npy.
**Domain**: data | **Risk**: low (~1h) | **Deps**: [T002]
**Acceptance**: codes_ts/{train,held}.npy + meta; shapes corretas.

### T004 — Treino AR baseline (bg)

**Intent**: `train_generator.py --model ar --bpe bpe_ts --corpus
corpus_ts --out artifacts/gen_ar_ts` — config ajustada (sem
warmstart Qwen — vocab diferente; manter 4L×896 ≈ 60-80M ou reduzir
se sinal fraco em smoke). Checkpoints + eval periódico.
**Domain**: ml | **Risk**: med (bg ~5-10h) | **Deps**: [T001]
**Acceptance**: gen_ar_ts/final.pt; curva de loss + amostras de
texto (fluência TinyStories).

### T005 — Treino NCM nativo (bg)

**Intent**: `train_generator.py --model ncm --vqvae tokenizer_ts
--codes codes_ts --out artifacts/gen_ncm_ts` — mesma config/params
que AR (paridade casada).
**Domain**: ml | **Risk**: med (bg ~6-12h) | **Deps**: [T003]
**Acceptance**: gen_ncm_ts/final.pt; curva por nível (coarse-first
esperado); amostras decodificadas via VQ-VAE decoder.

### T006 — Bench + eval end-to-end + report

**Intent**: `bench_generate.py` NCM vs AR (mesma semente/prompt):
tok/s, tokens/forward equivalente; `eval_samples.py` coerência;
acceptance nativo se instrumentável. Seção RUN-014 no report.md:
primeiro end-to-end do NCM nativo — speedup? qualidade?
**Domain**: ml+docs | **Risk**: low | **Deps**: [T004, T005]
**Acceptance**: bench json + amostras lado a lado + report com
veredito honesto (positivo ou negativo).

## Contract

executor: corpus+BPE+VQ-VAE+codes, AR e NCM treinados em paridade,
bench end-to-end medido, report atualizado.
tester: vocabulário 8k confirmado, paridade de params AR≈NCM,
veredito suportado pelos artefatos, sem processos deixados vivos
sem querer (treinos bg são intencionais e documentados).
