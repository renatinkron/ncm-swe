## Contract
Implementar apenas as alavancas com ganho medido no profiling
(run027-training-profiling.md): trunk-compile opt-in e batching de eval.
Prefix-cache de decode fica como design aprovado para braço futuro (D3);
engine C/Rust permanece adiada com justificativa registrada (D4).
Backward compatibility obrigatória: flags default-off, protocolo de
amostragem oficial inalterado, métricas científicas dentro do ruído.

## Tasks

### T1 — flag --compile-trunk no trainer (opt-in)
- `train_gen_official.py`: `--compile-trunk` → compila wrapper dos 4
  blocos (torch.compile, fallback eager silencioso se inductor falhar);
  `model.loss` chama o trunk compilado quando ativo.
- Critério de aceite: 20 steps seed-fixado compiled vs eager —
  |Δloss| relativo < 1e-5 e s/step −10%±3 no container lcm-infer-gcc;
  sem flag, comportamento byte-idêntico ao atual.
- Quality gate: flag default-off; nenhum run publicado muda de protocolo.

### T2 — batching de eval (geração n>1 em batch único)
- Verificar reprodutibilidade: `generate(batch_size=8)` vs 8×`batch_size=1`
  mesma seed — amostras podem divergir (RNG batelado); medir diferença nas
  métricas (dup/gap/CE) em vez de exigir tokens idênticos.
- Se métricas dentro do ruído documentado (±0,03 dup / ±0,1 gap):
  atualizar `sample_official.py --n` para batchar, documentando no header
  que a série v3/v4/v5 usou n sequencial e que batch preserva protocolo
  estatístico (T=1.0, top-p 1.0, l0 unigram).
- Se divergir materialmente: manter sequencial, registrar custo e NÃO
  alterar protocolo — ganho de eval não vale quebra de comparabilidade.
- Critério: JSON de eval batelado reproduz métricas dentro da tolerância.

### T3 — consolidar veredito no paper/log (se material)
- Atualizar `TIMELINE.md`/`SOURCES.md` + seção de métodos/limitações do
  paper com o resultado do profiling APENAS se T1/T2 entrarem em uso
  real (citar ceiling ~1,15× treino, decisão C/Rust, batch eval se adotado).
- Critério: números citados = números medidos em artifacts/prof/.
