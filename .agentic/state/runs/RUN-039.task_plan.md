# RUN-039 — Task Plan

## Demand

Ensinar o NCM a programar com transferência real de conhecimento (pedido do
user, máquina dedicada). Pré-condição medida: o VQ-VAE oficial perde 26% dos
tokens de código (rec 73.9% vs 100% em história; 2.0 ch/tok) — o canal de I/O
corrompe o conteúdo antes do gerador poder aprendê-lo. Caminho aprovado:
híbrido — BPE novo treinado em código + VQ-VAE existente.

## Design

1. Corpus de código local (stdlib Python + site-packages + scripts do repo,
   zero download) → shards em data/corpus_code/.
2. BPE-8192 treinado no corpus (mesma lib `tokenizers` do pre_tokenizer,
   pickles vocab+merges no formato oficial).
3. Teste de canal: (a) ids do BPE novo via VQ congelado = baseline
   emb-mismatch; (b) fine-tune SÓ da tabela de embeddings do VQ (encoder/VQ/
   decoder congelados) no corpus de código → recovery. Gate: rec ≥85%.
4. Se o canal passar: encode do corpus → code rows (N,641) → FT do
   LevelGenerator (cópia in-memory) → eval: % samples que parseiam/compilam
   como Python + CE curve + inspeção.
5. Loop contínuo de monitoramento: métricas em artifacts/ncm_code/.

## Branch

`main` — aditivo (scripts+artifacts+docs).

## Phases

| Phase | Mode | Tasks | Rationale |
|---|---|---|---|
| P1 | sequential | T1,T2,T3 | corpus→bpe→gate do canal |
| P2 | sequential | T4 | treino longo em background |
| P3 | sequential | T5 | docs |

## Tasks

### T1 — `scripts/code_corpus.py` (host)
Varre /usr/lib/python3*, ~/.venvs/*/lib/*/site-packages, scripts/; concatena
arquivos .py (dedup por hash, cap por arquivo) → data/corpus_code/shard*.txt.
Critério: ≥5MB de texto, stats.json com contagens.

### T2 — `scripts/code_bpe.py` (container)
Treina BPE vocab=8192 no corpus via tokenizers lib; salva
artifacts/ncm_code/bpe_code_vocab.pickle + bpe_code_merges.pickle no formato
do pre_tokenizer oficial; mede chars/token em amostras de código vs BPE
antigo. Critério: ≥3.5 ch/tok em código.

### T3 — `scripts/code_recon.py` (container)
(a) recovery com ids novos + emb table velha (baseline mismatch);
(b) fine-tune da emb table (8192×d, enc/VQ/dec congelados, AdamW, CE de
reconstrução) → recovery pós-tune; salva emb table como
artifacts/ncm_code/vq_emb_code.pt + metrics.json. Gate: rec ≥85%.

### T4 — `scripts/ncm_codetrain.py` (container, background)
Encode corpus via BPE novo + VQ(emb code) → codes_code.npy (N,641); FT do
LevelGenerator (cópia) → eval 32 samples: % que fazem ast.parse + % que
compilam; CE curve; samples dump. Métricas → artifacts/ncm_code/.

### T5 — docs
SESSION_HANDOFF.md + artifacts/report.md com veredito honesto.

## Contract

**Scope in**: `scripts/code_*.py`, `scripts/ncm_codetrain.py`,
`data/corpus_code/`, `artifacts/ncm_code/`, docs, `.agentic/`.
**Scope out**: `vendor/`, `artifacts/gen_ncm_v2/final.pt` (FT em cópia),
`artifacts/ncm_official` (emb tuning em cópia), outros checkpoints.

**Quality gates**:
- scripts rodam via `podman run --rm -i --network none -v $PWD:/repo
  -v $PWD/artifacts:/work/artifacts -w /repo localhost/lcm-infer`
- checkpoints originais intocados (mtime/bytesize)
- `git diff --check`; status restrito ao scope

**Acceptance criteria**:
1. corpus_code ≥5MB + stats
2. bpe_code pickles + ch/tok novo vs velho registrado
3. metrics.json: recon_recovery_mismatch, recon_recovery_tuned
4. codes_code.npy (N,641) uint16
5. ncm_code metrics: ce_first/last, ast_parse_pct, compile_pct, n_samples
6. docs com veredito honesto (inclui "não provou")
