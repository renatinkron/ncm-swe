## NC-1: spec-decode não medido (bloqueio de recurso)

O contrato pedia spec-decode no 30B-A3B — inviável sem derrubar o
llama-server do usuário (mlock'd, produção). Fix mínimo e honesto:

**Medir spec-decode num alvo menor da mesma família Qwen3** —
`Qwen3-1.7B` (Q8, ~1,8GB) como target + `Qwen3-0.6B-Q8_0` como draft.
Mesmo tokenizer/família que o 30B-A3B; cabe ao lado do servidor sem
conflito de RAM. Produz o **ratio real de speedup spec-decode em CPU
Zen2** — a quantidade que informa a decisão de ligar `--model-draft` no
servidor 30B (a dinâmica escala com o custo da verificação do target).

- R1: download Qwen3-1.7B Q8 → `~/models/`
- R2: `llama-cli` AR vs `--model-draft 0.6B --spec-draft-n-max 8`,
  mesmo prompt/semente/threads → `artifacts/bench_specdecode_thinkpad.json`
  com tok/s + acceptance stats dos dois modos
- R3: atualizar execution_report + report.md com o número e a
  recomendação calibrada para o servidor 30B

**Critério de aceite do fix**: spec-decode medido (tok/s + tokens
aceitos/draft), baseline AR casado no mesmo hardware/run; se a
aceitação for baixa demais para ganho, isso também é resultado válido.

**Fora de escopo permanece**: medir no 30B-A3B real — pendente de janela
autorizada para bounce do servidor do usuário (flag documentada).
