# RUN-015 Task Plan — ablação de níveis + corretivo NCM

## Context
RUN-014 provou speedup ×2,82 do NCM nativo mas com word-salad:
per-level loss l0~4,0 / l1~5,5 / l2-l5~7,0-7,3 (uniforme≈7,62).
Hipóteses concorrentes p/ o corretivo exigem diagnóstico prévio:
se níveis finos carregam pouca informação de reconstrução, a
hierarquia deve encolher; se carregam muita, o problema é só de
treinamento (currículo/mais steps/codebook menor).

## Branch
branch_strategy: local-only (sem remote); artifacts em artifacts/,
estado em .agentic/state/runs/RUN-015.*

## Tasks
- T001 [diagnostic]: script de ablação — carregar tokenizer_ts.pt
  (MiniMSRQ) + codes_ts/held.npy; para cada nível ℓ, decodificar
  segmentos com níveis ≥ℓ corrompidos/zerados; medir token-accuracy
  de reconstrução vs códigos completos. Saída:
  artifacts/level_ablation.json com acc_por_truncamento + amostras.
- T002 [decide+execute]: escolher o corretivo pelo diagnóstico:
  (a) se finos pouco informativos → re-treinar VQ-VAE com hierarquia
      curta ou codebooks afunilados, re-encode, re-treinar NCM;
  (b) se finos informativos mas intratáveis → currículo fine-first
      (peso por nível) retomando de gen_ncm_ts/ckpt.pt;
  (c) se plateau puro → retomar treino +3000 steps.
  Executar a opção escolhida com paridade de orçamento.
- T003 [evaluate]: re-bench NCM-vs-AR mesmas condições de RUN-014
  (n=8, temp=0.8, topk=40, seed=0) + eval_samples + inspeção manual;
  atualizar artifacts/report.md e execution_report.

## Acceptance / quality gates
- Gate G1 (evidence): toda afirmação de resultado citada a partir
  de artefato em disco (json/log/pt), nunca de log verbal.
- Gate G2 (quality): melhora de qualidade NCM medida por amostra
  inspecionada + distinct_word_ratio convergindo p/ faixa AR
  (~0,35-0,45); speedup só conta se acompanhado de veredito de
  qualidade honesto.
- Gate G3 (parity): qualquer re-treino usa mesmo corpus/steps/
  batch e mesmo seed-base de RUN-014 para comparabilidade.

## Contract
- T001: artifacts/level_ablation.json existe; contém accuracy por
  nível de truncamento e ≥2 amostras decodificadas por cenário.
- T002: opção escolhida registrada com justificativa no execution
  report; artefato de modelo novo OU ckpt retomado produzido.
- T003: artifacts/bench_ts2.json (ou equivalente) com speedup e
  métricas; amostras inspecionadas; veredito honesto registrado.
- Sem processos órfãos; sem claims sem evidência em artefato.
