# RUN-035 — Task Plan

## Demand

Experimento: condicionamento de l0 (código "conceito" do segmento, 1 token de
4096 classes) via features de um backbone LLM congelado (Qwen2.5-0.5B,
`~/models/qwen05-sft` — mesmo do RUN-005), em vez de depender só do q0
aprendido. Medir se features pré-treinadas carregam o sinal de conceito que o
gerador não aprende em orçamento CPU (l0≈8.22 ≈ marginal nos runs 019/020), e
se geração condicionada por prompt melhora.

## Scientific framing (design decision)

Para geração **incondicional**, l0≈entropia marginal é o ótimo teórico — não há
o que aprender além da prior (o recipe oficial *amostra* l0, não o prediz).
O teste válido de "transferência do treinamento do LLM" é o braço
**condicional**: prefix → feature congelada → l0. Isso é generation-valid
(prompt → conceito → continuação) e não exige retreinar o LevelGenerator —
usamos `generate(l0=...)` existente com `gen_ncm_v2/final.pt` congelado.

Hipóteses:
- H1: probe feature→l0 bate o baseline marginal em held-out (sinal existe)
- H2: geração com l0 do adapter é mais on-prompt que l0 unigram
- Controle: labels permutadas NÃO podem bater o marginal (sanidade anti-leak)

## Tasks

### T1 — dump de alinhamento segmento↔código (container)

Novo `scripts/dump_l0cond_rows.py`: reproduz `load_records`+`segs_of` de
`encode_official.py` sobre `data/corpus_ts_vq/shard-*.jsonl` (mesma split
sha1 8%), emitir por code-row:
`{row_idx, split, rec_id, prefix_ids (primeiros K ids BPE oficiais),
prefix_text}` → `artifacts/l0cond/rows_{train,held}.jsonl`.

- K default 16 (flag `--prefix-len`)
- Validar: `len(rows_train)==177175`, `len(rows_held)==15400` (vs meta.json);
  ordem de emissão idêntica à de `segs_of` (mesma função, mesma iteração)

Acceptance: arquivo emitido, contagens batem, spot-check de 3 linhas
(prefix_ids decodifica pra início do prefix_text).

### T2 — features congeladas do backbone Qwen (host venv `~/.venvs/ncm`)

Novo `scripts/l0cond_features.py`: rows.jsonl → tokenizer Qwen
(`transformers.AutoTokenizer` no qwen05-sft) → `FrozenQwen` (reusar a classe
de `train_level_heads.py` — importar, não duplicar) → salvar:

- `feat_E_{split}.npy`: mean de `embed_tokens` sobre o prefix (lookup, sem
  forward) — todos os rows
- `feat_H_{split}.npy`: mean-pool do último hidden — subsample via
  `--max-rows` (default 40000 train + 8000 held; tomar os primeiros N rows
  em ordem — determinístico)
- `l0_{split}.npy`: label = `codes[:, 0]` (l0 é 1 posição, 4096 classes)

Acceptance: shapes consistentes (feat (N,896), l0 (N,) int64), dtype ok,
números não-NaN.

### T3 — probe l0 (host venv)

Novo `scripts/l0cond_probe.py`: classificador `feature(896)→logits(4096)` —
linear + variante MLP-256 (flag `--arch`), AdamW lr 3e-4, batch 128,
`--steps` default 3000. Baselines no mesmo eval:
- `ce_marginal`: CE da distribuição marginal de l0 do train aplicada ao held
- `ce_uniform`: ln(4096)=8.318
- `ce_shuffle`: probe treinado com labels permutadas (mesmo pipeline)

Saída `artifacts/l0cond/probe.json`: por braço {E,H}×{linear,mlp}:
held CE, top-1, top-8 acc + baselines. Salvar melhor adapter por braço em
`artifacts/l0cond/adapter_{E,H}.pt` (state_dict + meta: feature type,
prefix_len, arch).

Acceptance: JSON com todos os campos; shuffle≈marginal (senão: leak — parar
e reportar); script roda sem erro.

### T4 — avaliação de geração condicionada (container)

Estender `scripts/sample_official.py` com modo `--l0 adapter:<path.pt>`:
para cada um de N prefixes do held (default 16, `--n`), computa feature
(mesmo instrumento do adapter), amostra l0 da distribuição do adapter
(mesmo sampler unigram: T/topk do official), chama `generate(l0=...)`, decoda.
Braços comparados nos MESMOS prefixes: `adapter` vs `unigram`.
Métricas por amostra: `prompt_cosine` (cosseno feature(prefix)↔feature(texto
gerado) — mesmo FrozenQwen como instrumento), `dup_rate`, `distinct_ratio`;
mais os textos. → `artifacts/bench_l0cond.json`

Nota: `sample_official.py` roda no container lcm-infer (vendored vqvae);
FrozenQwen é torch-puro — montar `~/models` via `-v $HOME/models:/models:ro`.

Acceptance: JSON com as duas séries de amostras + agregados; gerações não
vazias; mesmos prefixos nos dois braços.

### T5 — documentação

Atualizar `SESSION_HANDOFF.md` (seção nova) e `artifacts/report.md`
(RUN-035): setup, números H1/H2/controle, veredito (sinal existe? ganho de
condicionamento? limites), próximos passos. Resultado negativo também é
resultado — registrar como tal.
