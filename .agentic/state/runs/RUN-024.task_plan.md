# RUN-024 Task Plan — Avaliação incremental do braço v3

## Context
Braço v3 em treino (container `ncm_train_v3`): warm-start de
`gen_ncm_v2/final.pt`, corrupção linear por nível 0.75→0.25 (receita oficial),
10.000 steps, checkpoint a cada 500 (~18 s/step → ckpt ~2,5 h). Hipótese (do
RUN-023 + réplica WPS): corrupção decrescente reduz exposure bias e dup_rate.
Avaliar cada checkpoint conforme cai — não esperar o final.

## Branch
- decision: current_branch — avaliação contínua, artefatos e notas vão no
  trunk; sem feature branch (repo de pesquisa single-branch)
- worktree: n/a

## Tasks
- T001: script `scripts/eval_ckpt_v3.sh` (ou loop) que, para cada
  `ckpt_*.pt` novo em `artifacts/gen_ncm_v3/`, roda `sample_official.py`
  `--l0 unigram` com receita oficial (T=1.0, sem top-k) + sonda
  exposure-bias → JSON `artifacts/v3_eval/ckpt<step>.json`
- T002: avaliar ckpts já existentes (500..último) — baseline comparativa:
  `bench_l0uni_official.json` (v2, dup 0.1095, CE self 5.6481)
- T003: série de resultados em `.agentic/research/v3-linear-corruption-eval.md`
- T004: veredito quando sinal convergir OU treino terminar — atualizar
  paper (§4.4 → resultado do braço v3) + TIMELINE/SOURCES + push

## Contract
### Scope in
- eval por checkpoint (dup_rate, ce_self_gen, ce_held_gt, passes)
- série temporal de resultados + veredito + atualização do paper
### Scope out
- retreinos novos; mudança de arquitetura; GPU
### Quality gates
- mesma seed (0), n=8, T=1.0, top-k 0 — comparabilidade com baseline v2
- ckpt avaliado só após escrita completa no disco
- números no paper sempre com artefato JSON correspondente
### Acceptance criteria
- T001–T003 com evidência JSON; veredito documentado ou avaliação do final.pt
- DONE quando: T001–T003 registrados + (v3 final avaliado OU decisão
  documentada de convergência prematura/insuficiente)
- Cada JSON de avaliação reproduzível: mesma seed (0), n=8, T=1.0, top-k 0
- Números novos no paper só após artefato JSON correspondente
- Não matar o container de treino; avaliação roda em containers separados
- Checkpoint evaluation só após o arquivo estar completo (ckpt_*.pt + fsync)

## Held-out checks
- dup_rate e ce_self_gen devem ser comparáveis ao baseline v2
  (mesma seed/n/protocolo — divergência de protocolo invalida a comparação)
- Se l0 held CE subir vs v2, reportar — pode ser efeito da corrupção forte
