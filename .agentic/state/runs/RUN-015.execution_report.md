## T002 — corretivo escolhido [em execução]

**Opção (a′): codebooks afunilados** — `configs/vqvae_ts2.yaml`
`vqvae_vocab_size: [2048,2048,1024,512,256,128]` (era 2048 uniforme).
Justificativa: níveis finos são essenciais (T001) mas 2048 classes ×
até 128 posições em predição paralela ficou perto do uniforme com 3000
steps (l5 loss ~7,1 vs uniforme 7,62). Afunilar reduz a dificuldade
(l5 uniforme passa a ln128≈4,85) mantendo o caminho de informação;
recon_ce tem folga (0,152) para absorver degradação.

Incidente: primeira tentativa crashou — `checkpoints/vqvae_ts2.pt`
existia do run anterior (uniforme) e o trainer auto-resumiu → size
mismatch. Corrigido: novo run usa `--ckpt checkpoints/vqvae_taper.pt`
(mostra que resume implícito por existência de arquivo é frágil —
regra de projeto anotada).

Em voo: `train_vqvae` taper (PID 2548633, 2500 steps) → chain_ts3.sh
(flock+timeout+gate) → encode codes_ts2 → NCM gen_ncm_ts2 3000 steps.

**Experimento ampliado p/ 2 braços** (separa dificuldade-vs-computação):
- Arm A (dificuldade): taper + NCM 3000 steps — em voo via chain.
- Arm B (computação): NCM uniforme `--resume` 3000→6000 steps,
  4 threads (PID 2551936). Backup do artefato RUN-014 em
